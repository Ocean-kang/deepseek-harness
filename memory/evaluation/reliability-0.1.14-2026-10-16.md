# 记忆容量、隔离与真实质量验收

本机固定合成数据的十万条预热检索及跨数据库轻量操作达到目标。修复声明式规则丢失及负结果经验分类后，统一设置的十二例真实对照完成 72 个回答：记忆组 35/36、对照 18/36，所有相关案例均不低于各自对照，隔离、撤销和错误证据案例全部通过。固定样本收益验收通过；该结果不证明一般长期收益。

## 测量方法

测量使用 Windows、Node `v24.21.0` 和 Intel Core i7-10750H，通过构建后的生产 `SqliteMemory`、`TextMemoryRetriever` 和 Workspace 使用的 `StoragePool` 执行。数据、数据库、原始样本和冻结的 0.1.13 构建均保存在 `memory/`。测量安排了独立 CPU 窗口，但未采集系统级进程时间线；少量样本与另一路 Client 编译的重叠无法排除。这些结果是本机诊断，不是经过校准的 CI 性能预算。

| 测量项 | 明确范围 |
| --- | --- |
| 用户操作终点 | `retrieve()` 返回五条经授权复核的 L2 精确版本引用；轻量操作以另一数据库 `listProjects()` Promise 结算为终点。 |
| 固定工作负载 | 1 千、1 万、10 万条固定英文约束，含确定性的 `route0` 至 `routeN` 标记；L1 原始来源及一条 L2 通过生产提交建立，其余合成卡片通过数据库事务复制。 |
| 计时 | `performance.now()` 包围实际异步调用；种子创建、连接打开、首次索引、二十次预热、增量提交、增量检索及恢复分别记录，不包含模型或网络。 |
| 内存 | 同一诊断进程的 RSS 端点采样；不强制 GC，不声称峰值或独立进程的保留内存。 |
| 判定及负对照 | 预热 p95 ≤1,000 ms，竞争时轻量操作 p95 ≤200 ms；原实现一万条超时延目标、十万条总数超限，保留其失败原文。 |

固定查询为 `parser route731`，仅搜索 L2，每次最多返回五条。数据包含 1 千、1 万、10 万条有来源的合成 L2 约束。每组保存二十个预热样本，以升序第十九项作为 p95。基线背景卡片引用一个 L1 来源；修改后背景卡片引用独立的另一个 L1 来源，使新来源只有少量直接关联卡片，避免将必须保留的十万条直接关联材料误当成普通提炼上下文。两者的 L2 数量、文本和查询保持一致。

完整原始结果见[原实现基线](../.artifacts/capacity-baseline.json)、[修改后首次测量](../.artifacts/capacity-current.json)及[已保存索引的后续测量](../.artifacts/capacity-resumed.json)。首次测量中的 `incrementalQueryMs` 包含重建后该 L2 过滤语料的首次构建，不能作为纯增量开销；后续测量先预热同一过滤语料，再提交新知识，单独报告正确的增量结果。

## 容量与性能

| 种子 L2 条数 | 原实现预热 p95 | 修改后首次预热 p95 | 已保存索引复开后预热 p95 | 同语料增量提交后检索 |
| --- | --- | --- | --- | --- |
| 1,000 | 623.93 ms | 126.59 ms | 78.97 ms | 96.36 ms |
| 10,000 | 5,623.79 ms | 305.49 ms | 87.76 ms | 76.13 ms |
| 100,000 | 明确拒绝：候选总数超限 | 首次构建明确返回未就绪 | 187.44 ms | 111.08 ms |

十万条预热 p95 为 187.44 ms，低于 1,000 ms 目标。原实现的一万条结果超过同一目标，构成实际负对照；十万条则受原有总数上限阻止。修改后一万条首次预热比基线约快 18.4 倍，复开后的额外预热结果单列，不以较快的一组替换首次结果。后续测量的一千条、一万条数据库各包含前次增量检查新增的一条卡片，预热时实际分别为 1,001 和 10,001 条；十万条的前次增量检查尚未执行，预热时仍为 100,000 条。

一千条和一万条首次检索分别包含 1.56 s 和 10.66 s 的索引准备。十万条首次构建到达默认 60 s 索引同步预算时明确返回 `index-not-ready`，已完成页面保留；重新打开数据库后，40.28 s 完成余下构建并返回结果。该首次失败及恢复保存在原始结果中，不能解释为首次查询达到预热目标。重开数据库本身耗时 371.69 ms，数据库当时约 207.15 MB；该进程末次采样 RSS 约 144.40 MB。RSS 是进程端点样本，包含当时可达对象及运行时占用，未强制 GC，不代表峰值或严格保留内存。

十万条情况下，二十次真实生产池提炼准备与另一数据库的 `listProjects()` 操作重叠；所有轻量操作都在重操作未结算时开始，p95 为 1.15 ms，低于 200 ms 目标。一千条、一万条也分别在索引重建期间测得 0.81 ms、0.99 ms。这里验证的是存储池和数据库操作，不包含 Workspace 路由、模型延迟或浏览器渲染。

十万条新任务冻结 64 条已有知识，准备耗时 231.51 ms；同语料预热后，新卡片提交耗时 686.43 ms，包含提交后的索引追赶及检索耗时 111.08 ms。基线一万条任务冻结全部一万条已有知识。性能诊断没有把直接关联材料超预算的明确拒绝改成静默省略。

## 首次真实质量与成本

[固定案例](task4-cases.json)包含十二类输入：原有七类、L1 独有经验、L2 独有经验、两种矛盾执行状态及多会话干扰。每例执行一次真实学习，将相同学习数据库复制为每次对照的独立数据库；三个重复测量回答波动，不重复测量学习波动。记忆／对照顺序交替，记忆查询和回答请求均通过日志记录；回答使用框架 LLM 服务，未把它描述成真实 GUI Agent 的完整多步任务。

[最终真实实验结果](../.artifacts/quality-sYDOPb/report.json)及[汇总](../.artifacts/quality-sYDOPb/summary.json)记录 `completed: true`、`passed: false`。模型为 `deepseek-official/deepseek-flash`。初始隔离 home 未读到普通 DSH 凭据，随后通过显式凭据文件路径复用已有 `credentials-local` 服务，没有复制或输出密钥。沙箱请求返回 `TRANSPORT`，因此按仓库规则在宿主重试。首个宿主运行的默认高推理强度耗尽 2,048 token 提炼上限，返回 `INCOMPLETE_OUTPUT`，该运行中断后保存全部已有结果。

为保留累计 240 次请求上限，最终结果按推理设置分层：`negative-result` 和 `unrelated` 复用已经完成的高推理强度三组对照；其余十例在模型提供方支持的 `thinking: disabled`、`reasoningEffort: off` 下重新学习及回答，每对的两臂设置一致。`protocolDeviation` 和每例 `modelSettings` 明确记录这一偏离，因此结果不是统一推理设置的十二例实验。大小写判定曾将实际正确的 `Potatoes and butter` 判为错误；修正规则后直接重评已保存答案，没有为该规则重新调用模型。

声明式项目规则的丢失已复现：项目约束、更新决定、L1/L2 专属经验及多会话规则经常在 L1 返回 `empty`。共享两例的 L1 虽保留用户规则，实际 L2 请求返回 `[]`，没有生成可批准的 L3。实验没有捏造 L3 或共享回执；这两例无法实际执行批准和撤销，因此严格验收失败，不能将项目 B 的空召回解释为撤销通过。已存在私有 L1 的跨项目隔离案例通过。

两种矛盾工具结果都保留了没有成功执行验证的 L1，未产生 `executionEvidence` 或 `execution_verified` 污染，其三组记忆臂回答也均保留未验证结论。其中 `success: true, exitCode: 1` 的 L2 候选被输出校验拒绝，任务记录 `output` 失败，严格整例状态仍为失败；安全拒绝与学习完成情况分别保留。无命中的相关问题及共享任务失败使总体收益条件未满足，没有通过更换案例消除失败。

该完整实验使用的 L1 提示词将无有效执行内容导向空结果，知识提示词也强调执行经历。真实输出把显式用户规则称为未经执行确认的消息，说明“保留声明式用户约束”和“执行成功必须有一致工具证据”需要分别说明。随后修复新增 `l1-v4`／`knowledge-v5`，已有任务仍使用冻结的旧提示词及预算；用户声明只建立语义支持，不建立执行验证、人工确认或共享批准，方法仍要求程序核验成功执行。

运行器在每次框架请求分发前保守预留 UTF-8 输入字节加协议余量及完整输出 token 上限，执行累计总上限 240 次请求、200 万输入 token、25 万输出 token。前次尝试从原始报告导入，已导入条目不会重复计数；完整成功响应返回 usage 后只占用实际 token，未结算或缺少 usage 的尝试继续占用完整预留量。重试和扩展经过同一计数器；扩展默认关闭。已知 usage 按框架的互斥非缓存／缓存输入定义汇总。定价必须通过 `DSH_MEMORY_EVALUATION_PRICES` 指向显式 JSON 文件，提供 `currency`、`inputPerMillion`、`outputPerMillion`；没有价格或任一次 usage 缺失均不估算费用。

已按本次 DSH 源码核对计数范围：[请求重试插件](../../packages/llm/llm-retry/src/index.ts)在 `agent/request-error` 执行，固定实验直接使用辅助 LLM 服务，不启动回答 Agent，因此不经过该重试路径。[DeepSeek 适配器](../../packages/llm/llm-deepseek/src/adapter.ts)的请求内重试用于已上传文件 ID 失效，而[文件状态检查](../../packages/llm/llm-deepseek/src/request-files.ts)在没有文件时直接拒绝重试；本次固定学习及回答请求都是纯文本。该核对没有新增模型调用，也不将此计数保证推广到其他提供方或图像请求。

私有事实使用固定、不可由通用知识推出的标记，回答采用确定性格式及内容规则。程序分别记录答案、召回精确率和覆盖、步骤、延迟、学习／扩展／回答调用及 token。错误知识计数只评估矛盾执行状态案例中的错误执行验证；其余知识真实性标为未评估，不将零计数宣称为普遍错误知识比例。长期准确率、一般回答改善和真实费用均尚未建立。
