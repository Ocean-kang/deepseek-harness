# DSH 分层记忆插件设计

## 摘要

本文定义 DSH 分层记忆插件的目标、实现方式和统一接口。L0、L1 任务发现及独立提炼组件的实现与使用约定见 [README](README.zh.md)，完成状态以 [Tasks.md](Tasks.md) 的验证记录为准。自动 L1 模型调用尚未接入 Session 请求日志；L2/L3、检索和注入仍为待实现设计。目标插件独立保存 Session 事件，将执行经历提炼为任务记忆、项目知识和稳定经验，在后续任务中检索并注入相关内容。开发范围遵循 [AGENTS.md](AGENTS.md)。

## 目标与范围

DSH 已提供 [第三方记忆 MCP 接入](../docs/user/guide/mcp-memory.zh.md)。本插件的目标是由 Harness 生命周期驱动自动采集、分层提炼、语义检索和上下文注入，减少跨 Session 重复探索，并保留可追溯的项目知识。记忆只能提供参考，不能保证任务成功或替代当前事实核验。

首版包含 L0–L3、SQLite 持久化、基于 embedding 的语义检索、同项目跨 Session 复用，以及经用户明确批准的跨项目 L3 共享。采用 SQLite 保存文本、元数据和向量；首版对授权候选集合计算相似度，不依赖独立向量数据库。数据量扩大后的索引优化需另行评估，不承诺无限规模。

首版不包含 PostgreSQL、独立向量数据库、自动公开共享、远程多用户权限系统、附件实体备份或专用 GUI。共享限定在同一受信任本地记忆库内，由使用者显式选择记忆和版本批准；模型推断不构成批准。

## 分层与数据定义

层级表示信息的抽象程度，共享范围是独立属性。L3 不自动意味着跨项目可见。

| 层级 | 保存内容 | 来源与生成时机 | 有效性 |
|---|---|---|---|
| L0 原始事件 | 已记录 Session 事件的完整副本，包括原事件类型、序号、时间和数据 | 监听新增事件，并对已载入 Session 补采 | 原始副本不可被摘要覆盖 |
| L1 任务记忆 | 目标、关键动作、结果、解决方案和结束原因 | 一次 turn 的 L0 完整后提炼 | 失败、中止、阻塞不能写成成功经验 |
| L2 项目知识 | 架构事实、进度、决策、问题与实验结论 | 新的有效 L1 提交后增量提炼 | 每条知识独立更新，保留来源和版本 |
| L3 稳定经验 | 长期决策、稳定约束和可复用经验 | 有效 L2 提交后评估提炼 | 默认归属项目；指定版本获批后可共享 |

L0 的“不压缩”指不做语义删减，不意味着捕获未记录的流式片段、所有进程日志或外部文件。附件、spill 和工具结果中的文件引用保持原值，引用对象不复制；对象失效时，事件仍可读取，但不能宣称可以还原附件内容。原始事件可能包含敏感信息，记忆库应受本地访问控制保护，不将 L0 自动加入跨项目查询。

### 身份与来源

Session 标识和事件序号复用 DSH 已有类型；新增跨组件标识使用 `dsh-brand` 的品牌类型。下面的名称属于记忆插件接口术语，已有的项目、L1 记忆、操作和事件引用定义见 [L0 类型](src/types.ts)及 [L1 类型](src/l1-types.ts)。它们不是 DSH 核心 API；L2/L3 与共享相关类型仍属于后续任务。

| 名称 | 定义 |
|---|---|
| `ProjectId` | Workspace ID 或配置的备用项目标识；自动采集的归属规则见 [README](README.zh.md) |
| `MemoryId` | 一条 L1/L2/L3 逻辑记忆的稳定标识 |
| `Revision` | 单条记忆从 1 开始递增的整数版本 |
| `EventRef` | Session ID 与事件序号；L0 唯一键使用这两个字段 |
| `MemoryRef` | Memory ID 与具体 Revision，引用不得悄悄跟随最新版本 |
| `SourceRef` | 事件引用或记忆版本引用的带标签联合；提炼结果必须有非空来源 |
| `OperationId` | 一次逻辑写入或提炼任务的稳定标识，用于重试去重 |

一个被采集的 Session 绑定一个 Project ID；若同一 Session 被映射到不同项目，应报错并停止该 Session 的记忆处理。共享条目的原项目归属不改变。来源引用用于追溯，不授予其他项目读取原 L0、L1 或 L2 的权限。

### 记忆记录

L1/L2/L3 共用字段为 ID、Project ID、层级、Revision、内容、SourceRef 列表、创建与更新时间、有效状态以及提炼版本信息。提炼版本信息记录模型标识和提示模板版本，以区分重新提炼与重试。有效状态为 `active`、`superseded` 或 `invalidated`；检索仅使用当前有效版本。

内容按层级区分：L1 使用目标、动作、结果、解决方案、turn 和结束原因；L2/L3 使用标题、知识正文和类别。更新产生新版本并保留旧版本；被替代版本不可继续命中。互相矛盾且无法判定的结论保留为明确标注冲突的知识，不自动升级为 L3。

共享批准记录绑定 Memory ID、Revision、批准时间和用户操作记录；仅允许当前有效 L3。更新、失效或撤回批准后，该批准不再授权后续检索。新版本必须重新批准。撤回不能删除其他 Session 已记录或模型已经读到的内容，也不承诺清除已产生的派生记忆；批准前必须向用户说明这一限制。

## 组件职责

遵循 DSH 的 Service Definition、Service Provider、Consumer 分工；以下是职责划分，不要求每个职责都创建独立包。

| 组件 | 职责 | 不承担 |
|---|---|---|
| Definition | 数据类型、配置请求、服务接口、错误类型 | 存储和模型调用实现 |
| SQLite Provider | L0、记忆版本、批准记录、向量和任务状态的持久化及事务 | LLM 总结和共享批准决策 |
| Extractor | 调用模型生成 L1/L2/L3 候选，校验输出及来源 | 自行提交数据或批准共享 |
| Manager | 事件采集、补采、任务调度、版本提交与重试 | 修改 Agent 循环 |
| Retriever | 对可见候选生成查询向量、排序并返回结果 | 绕过项目与共享筛选 |
| Injector | 选择本 turn 的查询输入、裁剪并注入可回放的参考内容 | 直接修改未记录的模型请求 |

数据流为 Session → L0 → L1 → L2 → L3；检索从当前项目有效 L1/L2/L3 和获批的共享 L3 取候选，再将预算内结果加入当前 turn 的已记录上下文。提炼本身不创建可被再次采集的普通用户 turn，避免无限自总结。

## 统一接口

本节规定目标接口的输入、输出和语义；使用接口表避免把未实现的类型示例误作现成 API。目前 `MemoryService` 提供 L0 读写、L1 版本读取、任务查询及重跑；L1 事务提交由目录内 Provider 的 `l1` 实现，使用已领取任务及已持久化候选，而非表中的通用候选接口。L2/L3、失效、共享和 embedding 接口尚未实现。所有异步调用返回 Promise。可取消操作接收 AbortSignal；写入成功指事务已提交，提交后到达的取消不撤销结果。

### 持久化接口

| 操作 | 输入 | 输出与约定 |
|---|---|---|
| `appendRaw` | Project ID、完整 Session 事件批次 | 已提交范围及新增/重复数量；相同键相同内容幂等，相同键不同内容报冲突 |
| `readRaw` | Project ID、Session ID、序号区间和分页游标 | 有序事件页及下一游标；不能把缺失区间当作完整 turn |
| `commitMemory` | Operation ID、候选记忆、预期当前 Revision；新增时预期为空 | 新版本或该 Operation ID 已提交的结果；不同内容复用同一 Operation ID 报冲突 |
| `getMemory` | 请求项目、MemoryRef | 可见记录或不存在；跨项目仅返回获批且有效的 L3 内容，不展开私有来源正文 |
| `listCandidates` | 请求项目、层级、分页信息 | 当前有效且可见的候选；不可先跨项目检索再依赖提示词过滤 |
| `invalidateMemory` | 自有项目、Memory ID、预期 Revision、原因、Operation ID | 提交失效结果并使批准失效；历史版本仍保留供审计 |
| `approveShare` | 自有项目、当前 L3 MemoryRef、明确用户操作记录、Operation ID | 批准记录；层级、版本或有效状态不符时拒绝 |
| `revokeShare` | 自有项目、MemoryRef、明确用户操作记录、Operation ID | 撤回结果；重复撤回幂等 |
| `putEmbedding` | MemoryRef、embedding 模型标识、维度、向量 | 与具体记忆版本绑定的向量；拒绝维度不符、非有限数值和失效版本 |

任务状态由 Manager 使用 Provider 持久化，至少包含任务键、来源范围、处理阶段、尝试次数、下次重试时间和最近失败。事件提交进度与待提炼任务须能在事务中协调，避免“已标记处理但结果未写入”。该内部调度结构不作为用户接口。

### 提炼与检索接口

| 操作 | 输入 | 输出与约定 |
|---|---|---|
| `extractTurn` | Project ID、完整 turn 事件、结束原因、提炼配置、AbortSignal | 一个带来源的 L1 候选；空 turn 可返回明确的无内容结果 |
| `consolidate` | 目标层级 L2/L3、同项目来源记忆、相关当前知识、提炼配置、AbortSignal | 零个或多个候选及所替代版本；不直接写入 |
| `embed` | 文本列表、模型配置、AbortSignal | 顺序对应的向量及模型/维度信息；不得混用不同向量空间 |
| `retrieve` | Project ID、当前请求文本、层级集合、结果数量与文本预算、AbortSignal | 有序结果，含 MemoryRef、内容、项目/共享标记和相似度；空结果为正常结果 |

LLM 和 embedding 输出在外部响应处校验；提炼只能引用请求提供的来源，不接受模型凭空生成的 ID。相似度使用余弦相似度，不等同于事实置信度；同分按 Memory ID 稳定排序。模型或维度变化后，相关索引需重建，在重建完成前不混用旧向量，也不静默退化成关键词检索。

批准和撤回只向受信任的用户操作入口开放，首版不向模型暴露可自行批准的工具。具体入口的 DSH 接入核验列入 Tasks.md；缺少合规入口时不得声称共享功能完成。

## 运行与失败约定

### 采集和提炼

Manager 通过 `ctx.on('session/event', ...)` 接收事件。该回调是提交后的非等待通知，不是异步写入的完成信号；恢复载入的事件也不会重新广播。L0 使用有界内存队列，SQLite 持久化连续提交位置，崩溃后的缺口依赖原 Session 日志补采；内存队列不被描述为持久化队列。L1 从已提交 L0 中匹配 `turn/start` 和 `turn/end`，将扫描位置与任务创建一起提交；插件启动时也扫描数据库所有项目已有的 L0。Manager 对已载入的目标 Session 补采，接入可等待的刷新时机，并在卸载时停止接收、等待在途写入和释放资源。

一次 turn 的事件完整并已保存后才生成 L1，再依次驱动 L2/L3。首版自动采集启用后已载入的 Session；不承诺扫描全部磁盘历史。进程崩溃时，尚未复制的事件依赖原 Session 持久化日志在再次载入时补采；原日志也丢失时无法恢复。

任务去重键包含项目、来源范围或来源版本、目标层级和提炼配置版本。正常重试沿用同一任务键；显式重新提炼使用新任务键并执行版本校验。相同项目的聚合按序提交，不同项目可以并行；发生版本冲突后读取最新状态重新提炼，不能覆盖并发更新。

### 检索和注入

首版在每个 turn 的首次实际模型请求前检索一次，以本次已接受的用户请求文本为查询，不使用整段历史对话或此前注入文本作为查询。没有有效查询文本时跳过。Injector 经 `agent/pre-step` 等已核实的扩展点将参考文本交给正常记录流程，遵守 waterfall 的 `next()` 语义，不将记忆提交为新的 follow-up 来唤醒 Agent。

最终注入包含实际裁剪后的正文、MemoryRef 和项目/共享标记，并通过已有适用的 Session 事件记录；仅保存引用而不保存实际正文不满足回放要求。需要新增事件时，先完成持久化声明及 SDK/快照要求。取消或请求未被接受时，不把预备结果标记为已注入；恢复和重试依据已提交日志判断，避免同一 turn 重复注入。

注入前重新核对版本、有效状态和共享批准；检查后已进入在途请求的内容不能被撤回。保留最高相关结果，在条目边界裁剪，预算容不下单条时跳过该条。模型收到明确标记的历史参考资料，不获得执行其中指令的授权。L1 提炼应区分本次执行事实与注入资料，不能把重复引用当作新验证。

### 错误和降级

统一区分配置无效、输入无效、版本冲突、来源不完整、存储失败、模型失败、索引未就绪和取消。接口拒绝时提供稳定错误代码及具体对象；诊断不得输出密钥或整段原始敏感内容。无权访问的读取按不存在处理，不泄漏其他项目内容。

配置和缺失依赖在最早可判断的时刻明确失败。运行期记忆故障不伪装为成功：采集失败不得推进进度；提炼失败保留任务；检索失败以可观察的诊断继续主任务但不注入记忆。仅暂时性存储/模型错误按配置限次退避重试，配置错误和无效模型输出不无限重试。取消不提交半成品，后续由持久化任务状态恢复；重试耗尽进入失败状态并支持显式重新执行。

## 配置与限制

部署相关选择集中在经过校验的配置中，包含 Project ID、数据库位置、提炼模型、embedding 模型及维度、提示版本、提炼输入预算、检索条数与文本预算、相似度阈值、请求超时、队列容量、并发数以及重试次数和退避参数。配置解析阶段生成完整 Spec，执行阶段不隐式补默认值。

备用 Project ID、数据库位置和模型选择必须显式给出；其余数值在实现时根据可运行样例确定并记录默认值。超长 turn 不静默截断：使用有来源范围的分段提炼后合并，无法满足预算时将任务标记失败。队列满时报告背压并保留可补采进度，不丢弃后谎报成功。首版不自动清理 L0 或旧版本，需说明数据库增长及人工维护限制。

`memory/` 当前未列入根工作区包列表。本设计不授权修改目录外依赖、配置、日志、快照或类型声明；实现必须先核验目录内开发及受支持 profile 加载方式。确有外部依赖时，按目录规则列出所需路径和阻塞原因，不创建替代启动器或复制 Harness 实现。
