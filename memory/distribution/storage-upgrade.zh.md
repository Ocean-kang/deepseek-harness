# 异步记忆存储升级

[English](storage-upgrade.md) | 中文

## 变更

插件将 SQLite schema 5 升级到 6，新增历史导入进度、显式准入、清理标记、紧凑摘要/候选投影及 trace 分块。迁移回填投影和分块，保留原 L0/L1 记录及 Session 日志；任务输入移除重复的 L1 trace。旧数据回填或已准备旧任务首次提交时，原生 SQLite 内存可能临时容纳单条记录；常规读取使用有上限的投影和分页。知识输入排除完整 trace，并验证精确 L0 证据。已完成的提炼任务不会重新运行。

记忆数据库、任务、选择及检索方法使用异步存储，自定义 Cordis 调用方必须等待返回结果。存储 worker 故障可能导致写入结果未知：调用方必须报告此状态，在重新打开存储后检查持久化进度，不得盲目重复写入。trace 调用方读取 JSON 文本分页，拼接后再解析完整 trace；读取摘要不会加载完整 trace。

显式历史导入只允许已验证归属当前 Workspace 的所选旧 Session，并保留 fork 继承截点。导入遵循 `autoLearning`：开启学习时调度已配置模型调用，关闭学习时只复制 L0。未配置 `retention.maxAgeDays` 时自动保留期限清理关闭。清理仅删除已过期且不被保留记忆、待用选择、未完成任务、共享授权或活动 Session 依赖的完整 Session。仍被引用的证据可无限期超过所配置期限。

## 迁移

1. 停止 DSH，备份各[记忆目录](README.zh.md#data-and-configuration)，包括 SQLite sidecar 文件。通过受支持的 profile 安装，重启并刷新浏览器标签页。schema-5 读取器无法打开 schema-6 数据库；回滚使用备份。
2. 更新自定义调用方，等待记忆读取、任务操作和选择写入。将通过 L1 摘要获取完整 trace 的操作改为 `readTrace` 分页；读取时将精确记忆版本与 trace 游标配对保存。
3. 按需显式重试此前因大 trace 失败的知识提炼任务。完整 trace 仍被保存，知识输入排除它并通过精确 L0 证据验证结论。
4. 在归属当前 Workspace 的对话中预览历史 Session，选择来源并启动导入。完成或重启后检查持久化的逐来源进度。取消停止继续复制，但保留已提交数据和已排队学习。来源缺失或格式不支持时，先修复来源数据再启动另一次导入。
5. 保持保留期限清理关闭可保存全部采集数据。启用自动清理时配置 `retention.maxAgeDays`；`retention.intervalMs` 默认 86400000。手动执行前预览清理，执行后检查删除量及保护量。清理使数据库页可以复用；显式压缩可缩小物理文件，但可能等待数据库锁。
6. 重启后确认项目隔离、保留证据及待用选择。JSONL 冷读及单个超大事件仍可能超过插件的数据页预算；来源后端保持不变。
