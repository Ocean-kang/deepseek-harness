# 独立记忆召回与学习

[English](trigram-upgrade.md) | 中文

## 变更

独立记忆 0.1.8 使用 `trigram` 召回，并对一字及两字词项进行字面子串匹配。文本无命中且有可用记录时，独立入口默认通过已有 L1 模型进行一次带日志的查询改写，再检索一次。文本命中时不增加调用。模型输出不能提供召回事实。直挂 `textSearch: {}` 仍使用 `unicode61`，并关闭查询扩展。

新 L1–L3 任务还为每条最终记忆单独调用模型，生成一句话展示描述。该调用共用提炼任务的输入、输出及总调用预算；失败时不发布部分结果。L2/L3 按预算选择现有知识，即使只有一条来源记忆，也会对 L0 原文分组；必要时再由模型合并已检查的候选。可选的 `Knowledge.examinedEvents` 保存程序填写的已送入检查请求的原始事件引用；最终合并不同时重读全部原文。`supported` 仍是模型判断，不是事实保证。

已存 L0 事件及记忆版本保持完整。旧描述字段可省略，展示回退到可读正文。重试保留已存提示词版本，并按预算选择非必要的现有知识；必要祖先链超过预算的旧 v1/v2 任务须用当前设置创建新操作。新 v3 请求省略祖先摘要，服务端仍保留完整来源链。单条必要来源或证据事件超过输入预算时仍明确失败。旧插件读取方不理解新任务提示词版本；降级前应恢复升级前备份。

## 迁移

1. 停止使用记忆数据库的进程，备份完整数据库目录，包括 SQLite 辅助文件。在受支持的 DSH Web profile 安装 `deepseek-ai-dsh-memory-l0-0.1.8.tgz` 并重启；存储归属及启用规则仍见[安装说明](README.zh.md)。
2. 省略 `textSearch` 可开启独立入口的短词匹配及模型改写。若需只用完整词的纯文本召回，覆盖 `memory-l0` 配置并重启：

```yaml
- id: memory-l0
  config:
    textSearch:
      tokenizer: unicode61
      expandQuery: false
```

3. 若需短词匹配但不增加查询调用，使用 `tokenizer: trigram` 配合 `expandQuery: false`。开启扩展时，`expansionTimeoutMs` 默认 15000；格式错误或提供方失败会报错。搜索仍检查查询词项、候选、条目数及渲染字节预算。
4. 确保 `maxCalls` 容纳提炼、来源合并以及每条最终记忆的一次描述调用。通过已有重试 API 重试失败知识任务；总调用预算耗尽时须创建新操作。重新提炼旧 L1 或用当前配置创建任务，可生成描述及原文证据核查；不会自动改写历史。
5. 打开记忆，检查描述及行首选择框。测试短查询和同义改写，再检查已提交的上下文记录。辅助 L0 记录保留提炼、描述及查询扩展请求和结果；召回只能包含已存储且已授权的记忆。
