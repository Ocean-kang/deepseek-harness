# memory 开发规则

本文件适用于 `memory/` 及其全部子目录。遵循仓库根目录的 [AGENTS.md](../AGENTS.md)，并执行以下目录限制和 Ponytail 精简开发要求。这些规则约束 Agent 行为，不提供操作系统级写入隔离。

## 文件操作范围

- 唯一允许写入的目录是仓库根目录下的 `memory/`。新增、修改、删除和移动操作的全部目标都必须位于该目录内；移动的源路径也必须在该目录内。
- 代码、测试、配置、文档、生成文件、日志、缓存及任务产生的临时文件均须位于 `memory/` 内。不得修改外部工作区配置、依赖清单、锁文件、Git 配置或其他文件。
- 可以只读查看目录外的规范、源码和现有依赖，以核实接口并复用能力。写入前检查规范化后的实际路径；禁止通过 `..`、符号链接、目录联接或脚本间接写入目录外。
- 执行安装、构建、测试、格式化或生成命令前，核实其输出、缓存及临时文件位置。当前工作目录在 `memory/` 内不代表命令不会越界；无法确保写入范围的命令不得执行。
- 若正确实现需要修改目录外的调用方、共享实现、配置、快照、文档或持久化声明，停止依赖该变更的部分，说明所需路径和原因。继续可独立完成的范围内工作；不得通过复制外部实现、跳过必要检查或降低仓库要求来宣称完成。

## 需求与实现选择

将 [PROJECT.md](PROJECT.md) 作为需求规划参考。实现前核实当前源码中的接口、事件和扩展点；规划示例不代表已存在的 API，未来能力不构成自动实施授权。

- 先读完整需求和相关代码，追踪真实调用链，再依次判断：是否无需新增、是否可复用现有实现、标准库是否足够、原生平台能力是否覆盖、已安装依赖是否解决。满足要求时停止增加方案复杂度。
- 最后才编写最少必要代码；可以清楚、安全地写成一行时保持简短，不为行数牺牲可读性。优先删除冗余、采用直接实现并减少文件数量。
- 修复根因并搜索相关调用方，优先在共享实现中修复一次；共享实现位于目录外时执行上述范围冲突规则。
- 不引入未请求且非 Harness 必需的抽象、依赖、模板代码或未来扩展。已有简单方案能满足需求时，先说明替代方案，不擅自删减明确需求。
- 精简不得削弱输入边界校验、防止数据丢失的错误处理、安全性、可访问性或真实平台适配。同等复杂度下选择边界情况处理完整的实现。
- 对有意简化且需要说明的实现添加局部 `ponytail:` 注释；若有已知容量、性能或准确性上限，注明上限和升级路径。注释描述限制及安全使用条件，不复述代码或开发过程。

## Harness 开发要求

开发前阅读 [架构规范](../docs/architecture.md)；涉及生命周期、并发、子进程或清理时阅读 [防御模式](../docs/defensive-patterns.md)。根目录规则规定的架构和质量要求优先于 Ponytail 对抽象、依赖和检查数量的精简偏好。

- 通过已记录的插件扩展点实现能力，不修改 Agent 循环。遵循 Service Definition、Service Provider 和 Consumer 职责；仅在职责独立演进时拆分。注册与监听通过 `ctx.effect()` 或 `ctx.on()` 管理，并正确清理。
- 遵守严格 TypeScript、ESM、跨包导入和品牌 ID 规则，不新增 `as unknown` 断言。部署相关选项使用经过校验的配置；配置错误在最早可确定的位置明确失败。
- 模型可见输入必须能够从 Session 日志重建；新增记忆注入同样需要对应的 Session 事件，不得绕过日志直接拼接模型请求。
- 涉及持久化时遵循 [Session 格式状态](../docs/session-format-status.md) 和 [持久化类型变更声明](../docs/cookbook/reviewing-persistence-type-changes.md)。不得覆盖或删除已提交的格式代次；必要的外部声明更新受目录限制约束。
- 应用仅通过受支持的 `dsh` profile 启动。不得为目录隔离新增包 bin、演示应用入口或 SDK 参数逃逸路径。
- 同步维护受影响的 README 和 JSDoc，遵循 [文档规范](../docs/AGENTS.md) 及 [文字标准](../.agents/skills/dsh-prose-standard/SKILL.md)。必要文档位于目录外时报告范围冲突，不以目录内副本替代其权威来源。

## 检查与交付

- 非平凡逻辑至少保留一个可运行且能捕获行为退化的检查；复用现有测试设施，不额外引入测试框架。平凡改动不机械添加测试。
- 按 [测试规范](../docs/testing.md) 选择必要的单元、集成、真实 API 和录制会话快照检查。“一个检查”是最低要求，不是数量上限；Harness 要求的覆盖不得省略。
- 推送或宣称检查通过前遵循 [检查选择规则](../.agents/skills/dsh-pre-push-checks/SKILL.md)。仅报告实际执行的命令和结果；受写入范围、凭据或环境限制而未执行的检查必须明确列出。
- 交付前核对变更清单，确认全部修改和新增文件均在 `memory/` 内，且未覆盖用户已有改动。Markdown 链接使用正确的相对路径，段落保持单个物理行，文件末尾恰有一个换行。
- 提交 `git add` 和 `git commit` 之前需要检查目前修改是否都是在 `memory/` 文件夹内，还需要确认目前 `git branch` 是在 `memory` 而不是 `main` 。
